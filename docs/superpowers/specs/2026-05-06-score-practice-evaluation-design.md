# 曲谱练习评测 MVP 设计

## 概述

本设计为小提琴智能陪练小程序新增一条独立的“曲谱评测”练习流，用于评估用户演奏真实短句时的音准与节奏表现。第一版聚焦内置练习曲、固定 BPM 节拍器跟练、单旋律短句，输出综合分、分项分、错误定位和练习建议。

本功能不替换现有调音/基础检测流程，而是在首页新增单独入口，避免影响当前已成型的 MVP 链路。

## 目标

- 让用户可以从首页进入独立的曲谱评测流程。
- 基于内置练习曲完成一次短句级演奏评测。
- 在固定 BPM 下同时评估音准与节奏。
- 将评测结果转化为可执行的错误定位和练习建议。
- 将曲谱评测记录与现有基础练习记录存入同一集合，并支持历史页共存展示。

## 非目标

- 不支持用户上传曲谱、图片、PDF 或 MusicXML。
- 不支持后台录谱工具或运营配置平台。
- 不支持自由速度、rubato 或自动跟随用户速度。
- 不支持复音、双音、和弦或多声部。
- 不支持长篇大曲、多页谱和复杂乐章结构。
- 不支持 AI 文本点评或生成式分析。
- 不追求高保真五线谱渲染，第一版只需可用的练习曲展示。

## 用户场景

用户在首页点击“曲谱评测”，选择一首内置练习曲，查看曲目难度、拍号、BPM 和评测说明后开始练习。系统先给出若干预备拍，再以节拍器作为统一时基启动录音与评测。用户按固定速度演奏整条短句。练习结束后，结果页展示综合分、音准分、节奏分，并指出哪些音或哪些拍点存在偏高、偏低、偏抢、偏拖、时值不足或漏音等问题，同时给出简短的练习建议。用户可以保存记录并在历史页看到本次曲谱评测摘要。

## 产品范围

### 练习内容

- 第一版仅提供 2 首内置练习曲。
- 曲目为真实乐句外观，但技术上限制为单旋律短句。
- 曲目优先选择节奏清晰、音符边界相对明确的素材。
- 每首曲子包含固定 BPM，不提供自由改速。

### 首批曲目范围

第一版曲库固定为以下 2 首：

1. `练习音阶组合`
内容为 `B 大调音阶` 与 `g 小调音阶` 组合成一条练习曲目，作为一个评测条目存在。

2. `维瓦尔第 a 小调协奏曲`
限定为 Antonio Vivaldi 的 `Violin Concerto in A minor, RV 356`，作为另一条评测曲目。

第一版不再额外引入其他曲目。

### 评测能力

- 音准评测：判断目标音命中情况、偏高偏低趋势、平均偏差。
- 节奏评测：判断起音提前/延后、时值过短、漏音等问题。
- 综合评分：输出综合分、音准分、节奏分。
- 结果反馈：输出错误定位标签和面向练习的建议文案。

### 结果持久化

- 复用 `practice_sessions` 集合。
- 新增 `sessionType=score_practice` 区分曲谱评测记录与原有基础练习记录。

### 基础练习兼容约束

为避免历史页和存储层对两类 session 继续隐式耦合，第一版需要补充 `basic` 记录的最小字段契约：

- `sessionType`: `basic`
- `targetNote`
- `totalScore`
- `durationSec`
- `avgCentOffset`
- `startedAt` 或 `createdAt`

历史页不得再假设所有记录都具备 `targetNote` 和 `avgCentOffset`，必须按 `sessionType` 分支展示摘要字段。

## 信息架构与页面流程

### 页面流程

1. 首页新增 `曲谱评测` 入口。
2. 进入 `曲谱列表页`，展示内置练习曲列表。
3. 进入 `练习准备页`，展示曲目卡片、节拍、评测说明。
4. 进入 `曲谱评测页`，先进行预备拍，再进入固定 BPM 跟练。
5. 进入 `曲谱结果页`，展示分数、错误定位和练习建议。
6. 历史页展示 `score_practice` 记录摘要，与 `basic` 记录共存。

### 页面职责

#### 首页

- 提供 `开始练习` 和 `曲谱评测` 两条独立入口。
- 不改动现有基础检测主流程。

#### 曲谱列表页

- 展示每首曲目的名称、难度、拍号、BPM、预计时长。
- 承担选曲职责，不放复杂评测逻辑。

#### 练习准备页

- 展示当前曲目概览。
- 说明第一版评测适用于固定速度跟练。
- 告知评分由音准分和节奏分组成。
- 提供开始按钮。

#### 曲谱评测页

- 负责节拍器、预备拍、正式开始时间轴。
- 负责录音帧采集与 pitch frame 流处理。
- 负责实时展示当前练习状态和当前目标音提示。
- 不在此页做复杂结果总结，只保留必要的实时反馈。
- 以视觉节拍器为主，音频提示为辅，降低节拍器音频干扰录音识别的风险。

#### 曲谱结果页

- 展示综合分、音准分、节奏分。
- 展示错误定位摘要。
- 展示练习建议。
- 支持保存记录和再次练习。

#### 历史页

- 兼容两类 session。
- 以摘要形式展示曲谱评测记录，不在第一版扩展详情页。

## 评测设计

### 总体策略

第一版采用“固定 BPM 的时间窗口评测”。

系统在开始前通过节拍器给出统一时基，并为每个目标音符生成明确的评测窗口。录音分析得到的 pitch frames 会被归属到对应音符窗口，再分别计算音准和节奏表现。

该策略优先保证可落地与稳定性，而不是追求自由速度下的智能对齐。后续若升级到动态对齐，可复用本次定义的曲目数据结构、逐音结果结构和结果页反馈结构。

为适配现有端上 YIN 检测窗口，第一版曲库需要满足以下节奏限制：

- 不收录大量连续 16 分音符或更短时值的片段。
- 优先选择单音边界清晰、换音速度不过快的短句。
- 默认 BPM 控制在适合初学者稳定跟练的区间。

### 曲目数据模型

每首内置练习曲至少包含以下字段：

- `id`
- `title`
- `difficulty`
- `timeSignature`
- `bpm`
- `estimatedDurationSec`
- `notes`
- `focusTips`

其中 `notes` 为音符序列，单个音符至少包含：

- `pitch`
- `octave`
- `startBeat`
- `durationBeat`

可选扩展字段：

- `phraseIndex`
- `measureIndex`
- `displayLabel`
- `bowingHint`

第一版曲库录入方式采用本地静态配置，不引入后台配置能力。曲目数据直接随小程序代码发布。

### 曲谱来源与本地化约束

第一版新增一条强约束：曲谱素材必须先从网络获取并下载到本地，再整理为应用内置曲目。

具体要求：

- 网络来源必须是可追溯页面或可下载文件，不接受只凭口述录谱。
- 下载后的原始谱面文件需要作为项目内的源素材保存，便于后续校对和重新录入。
- 第一版只要求“下载并本地保存谱面源文件”，不要求在小程序运行时在线拉谱。
- 小程序实际评测使用的仍然是本地静态整理后的音符序列，而不是运行时直接解析 PDF。

推荐目录：

- `docs/sources/sheet-music/`
- `docs/sources/sheet-music/README.md` 记录来源链接、下载日期、曲目说明

第一版来源策略：

- `练习音阶组合`：从网络获取 B 大调与 g 小调小提琴练习音阶谱面，下载到本地后，再人工整理成一条评测曲目。
- `维瓦尔第 a 小调协奏曲`：从 IMSLP 获取 `RV 356` 对应谱面并下载到本地，再人工截取适合 MVP 的单旋律短句录入本地配置。

第一版明确不做：

- 自动 PDF 解析
- 自动 MusicXML 解析
- 在线谱面抓取后直接运行时评测

### 时间轴与评测窗口

进入评测页后，系统生成统一时间轴：

- `countInBeats`：预备拍数
- `startTimestamp`
- `beatDurationMs`
- `expectedStartMs`
- `expectedEndMs`

其中：

- 用户点击“开始”后立即进入预备拍阶段。
- `startTimestamp` 定义为“第一个目标音理论上应当开始发声的时刻”，而不是用户点击时刻。
- 所有 `expectedStartMs` / `expectedEndMs` 都以 `startTimestamp` 为零点计算，避免评测和 UI 使用不同基准。

每个音符会映射成一个评测窗口，并带上容错阈值：

- `targetNote`
- `expectedStartMs`
- `expectedEndMs`
- `timingToleranceMs`
- `pitchToleranceCent`

第一版建议默认阈值：

- `pitchToleranceCent = 50`
- `timingToleranceMs` 按 BPM 和音符时值换算，并设置一个保守的最小容忍值

时间轴模块需要提供统一查询接口，例如：

- `getExpectedTimeForNote(noteIndex)`
- `getWindowForNote(noteIndex)`

评测和 UI 必须共同消费这一套接口，避免重复计算造成漂移。

节奏分不要求帧级绝对精确，而以音符级命中和偏移趋势为准。

### 帧归属与逐音结果

现有端上音高识别继续输出 pitch frames。新评测模块按时间将 pitch frames 归属到对应音符窗口，并为每个音符生成结果：

- `targetNote`
- `startBeat`
- `durationBeat`
- `matched`
- `avgCentOffset`
- `timingOffsetMs`
- `holdRatio`
- `confidence`
- `issueTags`
- `noteScore`

其中 `issueTags` 可包含：

- `pitch-high`
- `pitch-low`
- `early`
- `late`
- `too-short`
- `missed`

帧归属的补充规则：

- 低于评测置信度阈值的 frame 不参与音符评分。
- 如果音符窗口内没有任何有效 frame，则该音符标记为 `missed`。
- `missed` 不视为“无数据跳过”，而是参与后续完成率和总分惩罚。

### 评分模型

第一版采用三层评分：

#### 音符级

每个音符独立评分，主要考虑：

- 是否命中目标音高
- 平均偏差是否超出阈值
- 起音是否明显提前或延后
- 时值是否明显不足

#### 分项级

将音符级结果聚合成：

- `pitchScore`
- `rhythmScore`
- `completionRate`

推荐初始权重：

- 音准相关权重高于节奏内部细项
- 音高命中优先于细微偏差
- 节奏侧以起音时机和时值完整度为主
- `completionRate = 命中或有效评估音符数 / 总音符数`

#### 总分级

综合分采用：

- `baseScore = pitchScore * 0.6 + rhythmScore * 0.4`
- `totalScore = baseScore * completionRate`

这样可以避免用户只演奏前半句或大量漏音时总分虚高。权重在第一版作为代码常量保留，不做用户可调配置，但实现上应集中定义，方便后续调整。

### 建议生成

结果聚合模块将音符问题标签转换为用户可理解的结论。建议以规则生成，不引入 AI。

示例输出方向：

- “前半句节奏偏抢，建议降速慢练。”
- “第 3 到第 5 音偏高，注意左手按弦稳定性。”
- “长音时值不足，收弓偏早，建议延长保持。”

建议规则需要明确触发条件：

- 连续至少 3 个音出现同类标签，可生成区段型建议。
- 若某类标签占整首曲目音符数的 30% 及以上，可生成全局型建议。
- 建议按问题集中度排序，优先输出最连续、最集中的 1 到 2 类问题。
- 若没有显著问题，则输出正向兜底建议，例如“表现很好，继续保持当前节奏与手型稳定性。”

“前半句”“后半句”以曲目音符序列的前后半区间定义，不依赖复杂乐句识别。

## 数据存储设计

### 集合策略

继续使用 `practice_sessions` 集合，不新增集合。

### Session 扩展结构

曲谱评测记录新增以下字段：

- `sessionType`: `score_practice`
- `pieceId`
- `pieceTitle`
- `bpm`
- `timeSignature`
- `summaryScores`
- `noteResults`
- `feedbackTags`
- `advice`
- `startedAt`
- `durationSec`

其中：

- `summaryScores` 至少包含 `pitchScore`、`rhythmScore`、`completionRate`、`totalScore`
- `noteResults` 保存逐音评测结果，作为后续可扩展基础
- `feedbackTags` 保存聚合后的问题标签，便于历史摘要复用

原有基础练习记录保持：

- `sessionType`: `basic`

历史页根据 `sessionType` 分支渲染，不打破现有记录读写。

推荐的历史摘要字段映射：

- `basic`: `targetNote`、`totalScore`、`avgCentOffset`、`durationSec`
- `score_practice`: `pieceTitle`、`summaryScores.totalScore`、`summaryScores.completionRate`、`durationSec`

## 交互与反馈原则

- 第一版不追求复杂实时谱面动画，但需要清楚告诉用户当前所处阶段：预备拍、评测中、已完成。
- 评测过程中应显示固定 BPM 的视觉节拍提示。
- 音频节拍器默认只用于预备拍，正式录音阶段默认关闭或降为极低提示强度，避免扬声器声音进入录音。
- 若录音质量不足或没有足够有效帧，应给出明确失败提示，而不是生成误导性低分。
- 结果反馈以“可执行练习建议”为中心，不只显示裸分数。

## 错误处理

- 麦克风授权失败：沿用现有授权提示与设置引导。
- 录音启动失败：提示重试并保留返回路径。
- 有效帧不足：提示环境噪声、距离和起音清晰度问题。
- 保存记录失败：允许用户重新保存，不阻断返回或再次练习。
- 曲目配置异常：不可进入评测页，应在准备页兜底提示。

## 测试策略

### 单元测试

重点覆盖纯函数逻辑：

- 音符窗口生成
- 节拍到毫秒映射
- 提前/延后判定
- 命中/漏音/时值不足判定
- 分项分和综合分计算

### 集成测试

使用模拟 pitch frame 序列验证整段评测结果：

- 全部命中时得到高分
- 偏高/偏低能正确落到音符级结果
- 整体偏抢/偏拖能反映到节奏分
- 漏音和时值不足能产生正确标签

### 真机测试

重点验证：

- 预备拍到正式开始的手感是否自然
- 节拍器不会显著干扰录音识别
- 连续短句练习是否稳定
- 中低端设备是否出现卡顿或明显延迟

### 数据验证

- `basic` 与 `score_practice` 两类 session 共存正常
- 历史页摘要显示正确
- 保存失败和读取失败的提示清晰

## 风险与控制策略

### 风险一：逐音对齐漂移

控制方式：

- 仅支持固定 BPM
- 仅支持单旋律短句
- 曲目优先选择节奏边界清晰素材

### 风险二：真实乐句导致识别不稳定

控制方式：

- 曲库初期只选短句
- 避免大量连音、装饰音和自由处理素材
- 结果页明确说明该模式适合固定速度练习

### 风险三：节拍器声音干扰录音

控制方式：

- 以视觉节拍器为主，降低对持续音频节拍器的依赖
- 预备拍阶段可短暂提供音频提示，正式录音阶段默认关闭或最小化
- 真机测试覆盖不同音量档位和不同机型外放场景

### 风险四：历史记录结构膨胀

控制方式：

- 历史页只展示摘要
- 详细逐音结果仅在本次结果页使用
- 后续若记录体积偏大，再评估裁剪 noteResults 或拆详情存储
